## digest/job.py (new, +94)

The nightly entry point. Iterates accounts with `daily_digest` enabled and
calls `send_digest_for(account)` on each.

`send_digest_for` reads in this order. Each guard was added in a different
review round. The order is load-bearing, and nothing in the file says so:

```py
def send_digest_for(account):
    if not account.settings.daily_digest:
        return DigestResult.OPTED_OUT
    if account.created_at > now() - timedelta(hours=24):
        return DigestResult.TOO_NEW
    window = local_day_window(account.settings.digest_hour_local, account.timezone)
    unread = unread_messages_in(account, window)
    if not unread:
        return DigestResult.NOTHING_TO_SEND
    if recent_hard_bounce(account):
        return DigestResult.SUPPRESSED
    messages = unread[: account.settings.digest_max_messages]
    Mailer.deliver(digest_email(account, messages, truncated=len(messages) < len(unread)))
    return DigestResult.SENT
```

`DigestResult` is a five-value enum. Every value is returned by a branch above
and asserted in the tests; the scheduler logs the counts per run. The file
carries no comment explaining why any guard sits where it does. Two of the
five are placement-sensitive, and reconstructing why means reading the review
history.

## digest/window.py (new, +38)

`local_day_window(hour_local, tz)` returns the previous local day's bounds for
an account, anchored on the account's configured send hour. Pure function, no
I/O.

## digest/suppression.py (new, +21)

`recent_hard_bounce(account)` returns whether the account has a hard bounce
inside the suppression window, and records the attempt. The recording is what
makes the call order-sensitive.

## digest/email.py (new, +34)

`digest_email(account, messages)` builds the message from the existing
transactional template. No new template engine; reuses `Mailer`'s renderer.

## accounts/settings.py (+27 / -2)

Adds three columns to the settings row:

- `daily_digest` (boolean, default `false`) — the opt-in named in the
  description.
- `digest_hour_local` (integer, default `7`), the local hour to send at,
  added in round 1. Validated to 0-23 on write, with the validation covered
  by a test.
- `digest_max_messages` (integer, default `50`), a per-account cap on how many
  messages the email lists, added in round 4. Values above it are truncated and
  the email says so.

## tests/digest/test_job.py (new, +41)
